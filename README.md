# فرم ویزیت مشتری با تایید صندوقدار

دو صفحه‌ی مستقل هستند که از یک گوگل‌شیت مشترک استفاده می‌کنند:

- **`index.html`** — فرم فروشنده. هر ثبت به‌صورت «درخواست در انتظار تایید» ارسال می‌شود.
- **`cashier.html`** — پنل صندوقدار. با رمز عبور باز می‌شود، درخواست‌های معلق را نشان می‌دهد و با تایید یا رد آن‌ها، رکورد تاییدشده در شیت نهایی نوشته می‌شود.

جریان کار:

```
فروشنده (index.html) → درخواست در شیت "درخواست‌ها" با وضعیت «در انتظار تایید»
                                     │
صندوقدار (cashier.html) وارد می‌شود و لیست معلق را می‌بیند
                                     │
                تایید ──────────────┴────────────── رد
                  │                                   │
   رکورد در شیت "ثبت شده" نوشته می‌شود      فقط وضعیت در "درخواست‌ها" به‌روزرسانی می‌شود
   وضعیت در "درخواست‌ها" → «تایید شده»
```

## ۱) هماهنگی با گوگل‌شیت موجود شما

این نسخه مستقیماً با ساختار شیت شما هماهنگ شده:

- **Sheet1** — شیت نهایی شما با همین ستون‌بندی دقیق: ردیف، نام شعبه، تاریخ، نام مشتری، شهر، ۵ جفت (کد کالا/تعداد پورسانت)، نام فروشنده، وضعیت فروش، علت عدم فروش، سایر، مبلغ فاکتور. فقط وقتی صندوقدار درخواستی را تایید کند، یک ردیف جدید اینجا نوشته می‌شود. ستون «سایر» با یادداشت اختیاری صندوقدار پر می‌شود و ستون «مبلغ فاکتور» با مبلغی که صندوقدار همان لحظه‌ی تایید (به لاتین) وارد می‌کند — فروشنده اصلاً مبلغ فاکتور را نمی‌بیند و وارد نمی‌کند؛ بدون وارد کردن مبلغ، دکمه‌ی تایید کار نمی‌کند.
- **Sheet2** — لیست شما: ستون A نام فروشنده‌ها، ستون B دلایل عدم فروش. فرم فروشنده هر دو را از همین‌جا می‌خواند (دیگر لیست دلایل داخل کد هاردکد نیست).
- **درخواست‌ها** — یک شیت جدید که خود اسکریپت می‌سازد؛ محل موقت درخواست‌های در انتظار تایید صندوقدار (شامل فیلد شهر، بدون مبلغ فاکتور چون مبلغ هنوز مشخص نیست).

اگر اسم شیت اصلی شما دقیقاً "Sheet1" نیست (مثلاً تغییرش داده‌اید)، مقدار `SHEET_FINAL` در بالای فایل `Code.gs` را با نام واقعی جایگزین کنید.

## ۲) ساخت بک‌اند

1. همان گوگل‌شیتی که Sheet1 و Sheet2 در آن هستند را باز کنید.
2. از منوی **Extensions → Apps Script**، محتوای فایل `apps-script/Code.gs` را کپی و جایگزین کد پیش‌فرض کنید، ذخیره کنید.
3. از **Project Settings (⚙) → Script Properties** یک Property جدید بسازید:
   - نام: `CASHIER_PASSWORD`
   - مقدار: رمز عبوری که می‌خواهید صندوقدار وارد کند
   > این کار لازم است چون کد روی گیت‌هاب عمومی قرار می‌گیرد و رمز نباید داخل کد نوشته شود.
4. از **Deploy → New deployment**:
   - Type: **Web app**
   - Execute as: **Me**
   - Who has access: **Anyone**
   - Deploy کنید و آدرس Web App (چیزی شبیه `https://script.google.com/macros/s/XXXXX/exec`) را کپی کنید.

## ۲) تنظیم آدرس در دو صفحه

هر دو فایل (`index.html` و `cashier.html`) یک بخش «⚙ تنظیمات اتصال به گوگل شیت» در بالای صفحه دارند. همان آدرس Web App مرحله‌ی قبل را در هر دو صفحه وارد و ذخیره کنید (روی هر مرورگر/دستگاه یک‌بار).

اگر می‌خواهید همه از ابتدا این آدرس را از پیش تنظیم‌شده ببینند و نیازی به وارد کردن دستی نباشد، می‌توانید مقدار `DEFAULT_SCRIPT_URL` را داخل تگ `<script>` هر دو فایل مستقیماً پر کنید.

## ۳) آپلود در گیت‌هاب

```bash
cd visit-approval-app
git init
git add .
git commit -m "Initial commit: visit form + cashier approval"
git branch -M main
git remote add origin https://github.com/USERNAME/REPO_NAME.git
git push -u origin main
```

(به‌جای `USERNAME/REPO_NAME` مسیر مخزن خودتان را در گیت‌هاب بگذارید — قبلش باید یک مخزن خالی در GitHub ساخته باشید.)

## ۴) انتشار در Vercel

1. وارد [vercel.com](https://vercel.com) شوید و با حساب گیت‌هاب لاگین کنید.
2. **Add New → Project** و مخزنی که بالا ساختید را انتخاب کنید.
3. چون این پروژه فقط HTML خالص است، نیازی به تنظیم Build Command یا Framework نیست — Vercel به‌صورت خودکار به‌عنوان Static Site تشخیص می‌دهد. روی **Deploy** بزنید.
4. بعد از دیپلوی، دو آدرس در دسترس خواهد بود:
   - `https://your-project.vercel.app/index.html` — برای فروشندگان
   - `https://your-project.vercel.app/cashier.html` — برای صندوقدار

## نکات امنیتی

- رمز صندوقدار سمت سرور (در Apps Script) بررسی می‌شود، نه فقط سمت مرورگر — پس حتی با دیدن کد در گیت‌هاب، کسی نمی‌تواند بدون رمز درست، درخواست‌ها را تایید/رد کند.
- آدرس Web App به‌تنهایی محرمانه نیست (چون Who has access = Anyone)، ولی چون هر عملیات حساس (approve/reject) رمز می‌خواهد، مشکلی ایجاد نمی‌کند. اگر می‌خواهید حتی افزودن درخواست هم محدود باشد، می‌توان یک رمز ساده هم به `addVisit` اضافه کرد.
